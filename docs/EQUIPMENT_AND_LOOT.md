# 装备与掉落设计 v0.1

状态：设计与独立 Godot 原型已完成，尚未接入当前 Player、敌人、宝箱、HUD 或正式存档。数据与概率为可调初值；特殊效果只有规格，没有战斗实现。不能把本文件中的装备描述当作当前已可游玩的能力。

## 1. 装备应该带来什么

每件掉落回答一个问题：它会让我怎么打？品质决定能力预算，武器决定打法，护甲决定容错与机动取舍，饰品补足资源或强化专长。更高品质不应无条件覆盖所有低品质装备。

当前运行版本只有 weapon / armor 两个装备位；RING 类型虽存在，但没有真正的饰品位。新规格采用 weapon / armor / trinket 三槽，每槽一件，不加头盔、手套、鞋子和双戒指。所有装备只在本局生效，永久保留战绩；不加耐久、强化、鉴定、套装收集和随机词缀。

装备与“遗物”区分：装备可以在背包替换，是可调整的基础打法；遗物是在层间获得且本局锁定的规则选择。效果相同时按上限合并，不叠乘两份同类触发。

## 3. 属性和特效必须真实生效

现有代码检查发现：吸血等字段虽然被汇总，尚未实际应用；护甲当前只在格挡分支减伤；负移速与基础移速的计算也需要修正。接入前先修这些问题，不让道具说明领先于实际功能。

统一建议：

- 攻击 = 角色基础攻击 + 武器攻击。全局增伤为同一加法区间，最后乘暴击倍率；装备不能在 _recalc_stats 中反复累加到基础值。
- 普攻射击间隔 = 基础间隔 × 装备间隔倍率 × 技能倍率，下限暂定0.18秒；Q固定连射节奏另行处理。
- 移速 = 基础移速 × (1 + 所有移速百分比之和)，总百分比限制在-25%到+25%。站立瞄准与负面效果另列，避免复用含义不同的旧字段。
- 对正伤害：减甲后伤害 = max(原伤害 × 0.40, 原伤害 - 总护甲)；格挡再乘(1 - 格挡减伤)，格挡减伤上限75%，最后伤害至少1。原伤害≤0或无敌时直接0；持续伤害是否能被格挡另定，不默认为全部可挡。
- 暴击率上限35%，暴击倍率上限2.0；攻击间隔与穿透共同影响DPS，不能只比较单箭伤害。
- 吸血按目标实际扣除的生命计算，不按过量伤害、护盾吸收或原始伤害计算。持续伤害、回声箭首版不触发吸血。
- 增加生命上限不主动治疗；降低上限时夹紧当前生命，反复换装不能回血。法力上限同理。
- 红药计划改为回复35%最大生命，蓝药回复40%最大法力；当前旧药水是全回复，不能直接套用新掉率后仍保留无限强补给。

### 触发事件约定

事件至少携带 attack_id、owner、target、origin、effective_damage、is_critical；origin 区分 normal / skill_q / echo / damage_over_time。只在实际命中时计数，射空不计算命中。

| 效果 | 触发规格 |
|---|---|
| 连续命中 | 普攻与Q主箭共用计数；同一目标第三次命中消耗计数归零；2秒无命中、目标死亡或换武器时清零；回声不计 |
| 翻滚后增伤 | 翻滚结束发放一次标记；第一支成功发射的普通箭消费，射空也不退还；Q与回声不消费、不获益 |
| 回声 | 只统计普通攻击发射；每3次发射触发一次，追加箭不再次触发发射计数；换武器清零 |
| 穿透 | 每支箭记已命中目标ID；每个目标只结算一次；遇墙终止；装备与遗物同时提供时首版上限仍为1次穿透 |
| 同目标增伤遗物 | 若与守望者同用，合并为更高的一个第三击增伤，不乘40%再乘50% |
| 复活护甲 | 消耗状态存于本局玩家状态，不能放在可换装重建的装备缓存里；退出重进也不刷新 |

这些触发规则尚未写入战斗代码；目录脚本的 effect_id 只是待实现接口标识。

## 4. 掉落机制：先来源，再品质，再装备位，再模板

每次奖励调用必须有唯一 event_id，例如 `floor2:room4:enemy7`。按顺序处理：检查已结算 → 决定是否掉装备 → 抽品质 → 抽装备位 → 抽模板 → 独立决定药水。

**以下品质概率均是“已经获得一件装备以后”的条件概率，不是击杀直接掉该品质的概率。**

| 来源 | 装备数量/概率 | 药水 | 设计意义 |
|---|---|---|---|
| 普通怪 | I/II/III基础10%/12%/14%；带普通怪保底 | 独立12%概率一瓶 | 探索小惊喜，不依赖无限刷怪 |
| 精英 | 必掉1件 | 独立35%概率一瓶 | 冒险投入有确定回报 |
| 普通宝箱 | 必掉1件 | 必掉1瓶 | 可靠补给节点 |
| 危险宝箱 | 挑战完成后必掉2件 | 不额外掉药 | 可跳过的高风险奖励，避免奖励反过来立即抵消全部消耗 |
| 第三层Boss | 必掉2件；第一件紫以上，第二件蓝/紫 | 固定红、蓝各1 | 完整收尾，首版无Boss后战斗时药水仅为展示性掉落，可在接入时取消 |

药水随机位红55%、蓝45%，与装备池独立；不做未公布的低血量暗改概率。危险宝箱在守卫死亡、房间挑战结束之后才调用奖励，不能“先开箱拿装备、再逃跑”绕过风险。

### 保底、防重复与空槽倾向

- 普通怪连续8次没掉装备，第9个合格击杀必掉一件；成功后重置。计数跨层延续，本局结束清空。
- 精英/宝箱/Boss不推进也不清空普通怪保底；药水不会重置装备保底。
- 开发刷怪、召唤怪、已结算对象不属于合格击杀。接入方须把它们排除，不可将调试刷怪直接送入 normal。
- 因保底存在，长期平均掉率高于基础概率，约为16.32%、17.56%、18.85%；短局结果仍有波动。
- 装备位基础权重：武器45、护甲35、饰品20。空装备位权重×1.5，再归一化；不是固定额外50个百分点。
- 同一品质与装备位内，已在装备栏或背包持有的模板权重×0.25；不改品质概率、不保证绝对不重复。候选只有一件时仍会重复。
- 同一宝箱/Boss本次已抽到的模板也加入降权列表。传入的 owned_ids 必须来自当前角色状态，不是所有历史见过的物品。
- 原型不会主动回收低品质装备，也不强制替换玩家当前装备。

### 单局掉落预算

建议主路线约24–30个普通怪、前两层各1个守门精英、三层合计3个普通宝箱、终层1个Boss，主路线装备目标约11–13件；额外精英与危险宝箱最多再增加约3件。由于局长和保底边界，必须按真实关卡模拟验证，不能把长期掉率当短局承诺。

每层以2–4次值得比较的装备选择为目标。背包保留20格，拾取不自动装备；满包物品留地，提示“背包已满”，避免奖励消失。地上展示品质色、槽位图标、名称，交互面板比较主要属性和完整特效，不能只显示一个绿色向上箭头。

不会为了防重复额外引入分解货币和商店。重复物品可以放弃；要检查玩家是否因过多无用掉落频繁整理背包。

func begin_adventure(seed_value: int) -> void:

## 6. 存档、随机数与反复开箱

地图随机数与掉落随机数分开实例，避免装饰生成改变装备掉落。掉落 start_run 只在新冒险调用；下层不重置，读档调用 restore_state。

导出内容：版本、RNG种子与状态、连续未掉次数、实例序号、已结算事件集合。64位随机数以字符串存，避免JSON数字精度丢失；已经测试JSON往返后后续50次奖励完全一致。

装备存储需要模板ID、实例ID、版本、生成时stats和effect_id快照，不能只调用旧 ItemData.from_name 重建新对象，否则更新配置后旧存档能力会静默改变。版本迁移与模板快照的优先级必须明确，首版建议读生成快照。

接入安全要求：

- 同一奖励事件只处理一次，包括“本次未掉落”也必须记为已处理，不能重调直到掉落。
- 奖励结果、玩家/地上物品状态与已结算事件需要在同一个冒险快照保存，不能先持久化claim再丢失物品。
- 原型 roll 是有状态的同步内存计算，不具备磁盘事务或崩溃恢复能力；这些是接入方工作，不是此脚本已完成能力。
- 与层间存档策略统一：读档若回到本层入口，则回滚本层所有新增收益、事件集合与随机状态；同样路线得到同样掉落，不能保留收益后刷同一箱子。
- 非法来源/深度、空事件ID、重复领取均返回error且不推进随机数。不要忽略error直接发奖励。

## 7. 接入顺序与范围控制

当前18件是设计库，不等于本轮承诺实现18种能力。上一版10日路线图没有覆盖三槽UI、装备快照和全部装备特效；完整接入预计追加约4–6个工作日，属于初估，不能默认为仍在原10天内。

1. 先落实基础属性、饰品位、背包比较与版本化快照，纠正当前护甲/移速/吸血说明不一致。
2. 首批9件：三槽各白、绿及第一件蓝装；只接穿透和对精英伤害两类新效果。配置掉落池仅启用已实现效果的物品；不足的品质档暂回退到最高可用低档，并在UI与测试中同步，不准掉落空效果紫橙。
3. 再做守望者、影步披风、静息石等；新增效果逐个加入白名单，才能进入正式掉落池。
4. 最后加入紫橙装与全量概率表。终战后橙装的玩法价值取决于后续挑战是否立项，首版可只展示战利品，不强迫增加无尽模式。
